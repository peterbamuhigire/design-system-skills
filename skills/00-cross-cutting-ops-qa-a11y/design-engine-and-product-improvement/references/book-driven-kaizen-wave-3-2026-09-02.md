# Book-driven Kaizen Wave 3: design application

Use this reference for visual systems, interfaces, dashboards, images, documents, slides,
spreadsheets, and rendered QA.

Owning skill: [Kaizen owner](../SKILL.md).

## Transfer controls

- Begin with task, audience, decision, and information hierarchy. Use accurate encodings,
  comparison, exception context, proximity, similarity, enclosure, connection, and restrained
  non-data decoration.
- Treat image work as a task-specific quality pipeline: acquisition/sampling, enhancement or
  restoration choice, colour, compression, segmentation/feature use, output fidelity, and
  meaningful measurement.
- Test rendered states, responsive behavior, typography, contrast, text alternatives, focus,
  motion, content density, and performance. Preserve a human-readable fallback for generated
  or AI-assisted output.
- Record baseline, reversible experiment, visual/accessibility guardrails, acceptance evidence,
  rollback, and re-audit; standardise only after evidence.

## Boundaries

Visual books provide principles, not current browser, codec, ML, accessibility, or vendor
authority. Do not copy historical tool assumptions or use decorative complexity as proof of
quality. Mark unavailable renders, user tests, or platform evidence `NOT_ASSESSED`.

## Measures and routing

Track task completion, comprehension, error rate, visual defects, contrast/text-alternative
coverage, layout shift, asset size, rendered fidelity, and reviewer agreement. Route to the
design doctrine, accessibility, image, dashboard, document, and launch gates.

## Currentness gate

Verify accessibility against WCAG 2.2/WAI guidance and browser/format claims against current
primary sources. Record access date, freshness, support, uncertainty, and review trigger.
