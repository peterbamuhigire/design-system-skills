# Design-system engine book upgrade - August 2026

This record documents the design-system-only implementation from the sixteen-book study. The
books remain outside the repository. No raw book text, OCR dump, or reconstructed pages are copied
here.

## Source register and limits

| Source | Use in this engine | Limitation |
|---|---|---|
| *Dynamic Characters* (3DTotal) | Silhouette ideation, variation, anatomy-under-design, value separation, story-driven gesture, camera/framing, modeler handoff | Photoshop workflow and examples are dated; principles are treated as transferable craft, not current software guidance |
| *Digital Storytelling* (Carolyn Handler Miller) | Interactive choice, point of view, modular structure, character/emotion, information plus interactivity, development documents, audience fit | Historical technology/platform examples are dated |
| *Video Game Storytelling* (Evan Skolnick) | Conflict/tension, game story versus player story, narrative believability, character documents, shared intent, narrative-team integration | Narrative patterns are heuristics, not universal templates |
| *Designing for AI* (Arash Sadr) | Problem-first AI selection, value mapping, model/system/input/output separation, inferred data, disclosure, human control, correction, drift-aware review | Early release; only available chapters were read. Unavailable chapters are not treated as evidence. Current legal/platform claims require verification |
| *Applying the Kaizen in Africa* | Participatory, incremental, low-budget improvement; observation, standardisation, QC Story, PDCA, waste removal, management ownership | African cases inform adaptation, not guaranteed outcomes for this practice |
| *LEAN: Ultimate Collection* | Build-Measure-Learn, baseline, validated learning, small batches, Five Whys, pivot/persevere, KPI cadence | Compilation is uneven and duplicated; original authorities remain preferred for exact standards |
| *Paid for Your Perspective* | Evidence-bounded expert positioning, screening, compliance, bounded claims, practical judgment | Expert-network examples do not define design certification or legal advice |
| *Anatomy for Artists* (Tom Fox) | No implementation claim | Extraction is unusable: one line, `Part1`; anatomy guidance must be re-ingested from a lawful readable source |

## Implemented capability changes

1. Added a design-engine/product-improvement skill with an eight-step Kaizen cycle, evidence
   matrix, capped 65/100 audit, 95/100 improvement target, rollback, standardisation, teaching,
   and re-measurement.
2. Added gesture/silhouette/story composition as a concrete design skill. It uses Dynamic
   Characters for thumbnails, readable outer shape, story intent, pose exaggeration, value
   separation, camera distance, and production handoff. It does not claim to teach anatomy from
   the unreadable Tom Fox extraction.
3. Added AI interface disclosure/control/correction/drift as a concrete UI skill. It requires
   problem-first AI selection, system mapping, input/output disclosure, user correction,
   approval, fallback, and post-launch drift review.
4. Strengthened information architecture with narrative information architecture: audience,
   point of view, tension, choice, consequence, reveal, and recovery are mapped without making
   navigation theatrical or hiding task-critical information.
5. Strengthened product audit evidence to include readability at intended scale, failed states,
   AI trust states, provenance, accessibility alternatives, handoff, and re-measurement.
6. Strengthened critique and visual QA so iterative review produces a small experiment, a named
   decision, evidence, and a standardisation or rollback outcome.
